# ADR 0010：可回滚建模编辑与容量限制

状态：已采纳（2026-10-13）；关联 GS-008。

## 背景

现有建模操作直接修改 Model，多步分配或几何失败会留下实体；Session 在建模后才发布 tag，tag 容量错误也可能留下模型。普通深拷贝回滚还会使临时 ID 在下一次分配时复活。

## 决定

- 先使用完整状态快照 + RAII 事务：返回 Err 或栈展开时恢复几何、八类拓扑、精度与容量设置；返回 Ok 提交。支持嵌套，内层提交仍可被外层回滚。事务本身只保证原子性，不代替 check_body。
- Arena 可克隆，快照共享独立的原子代数分配器，每次插入取得新的 generation，删除不循环代数。回滚不回退代数分配器，失败操作泄漏的临时 ID 永不别名后来插入的值。代数耗尽返回 CapacityExceeded。
- 低层 ID 只在其所属模型/arena 中使用；事务回调必须编辑提供的存储，不能用另一个 Model 或 GeomStore 替换它。未经提交不得对外发布临时 ID。
- 新增 Arena 的活动实体上限、GeomStore 两类上限和 ModelLimits 的十类上限。默认不增加用户可见的低限；超限返回既有 CapacityExceeded。上限同时用于确定性资源控制和真实构造路径上的分配失败注入。
- 既有基础体入口使用 Model 事务。内部构造助手避免通孔调用长方体时重复快照。
- Session 增加可选的 start_with_limits，保留 start 和所有绑定签名。body 发布前预检并预留 tag 容量，在事务中构造并运行不变的 check_body；有故障/未执行检查则回滚并返回明确错误。成功后发布已预留的 tag。
- 对批量查询生成 tag 也先整体预检和预留，避免容量错误只修改一部分 tag。使用测试内的 tag 上限注入验证，不向 C ABI 增加选项。

## 代价与限制

快照成本随已有模型大小增长，作为 pre-alpha 正确性实现；优化为日志或持久化存储前须保留相同失败测试。Clone 内部仍可能遇到系统级不可恢复 OOM；本轮不宣称捕获 allocator abort 或进程终止。显式容量限制和 try_reserve 错误可诊断，事务覆盖普通 Result 错误及 Rust 栈展开。RawEditor 仍是未经检查的底层接口，直接使用它的调用方自行负责有效性。未来裁剪附属表须加入快照。
